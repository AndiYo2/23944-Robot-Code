 Autonomous Action Framework - Design Plan

 Overview

 Create a framework to quickly build autonomous routines using a fluent API instead of hand-coding state machines. This will reduce code from ~200 lines with 11 switch cases to ~50 lines of declarative action sequences.

 Architecture: Hybrid Fluent Builder + Command Pattern

 Core Components

 1. Action Interface - Base contract for all actions
 2. Action Implementations - Concrete classes for each action type (Move, Shoot, Catalog, Intake, Limelight, Delay)
 3. ActionGroup - Composite container for sequential/parallel execution
 4. ActionExecutor - Central state machine interpreter (replaces pathState switching)
 5. AutonSequence - Fluent builder API for constructing autonomous routines

 Example Usage

 Before (manual state machine):
 protected void autonomousPathUpdate() {
     switch (pathState) {
         case 0:
             if (pathTimer.getElapsedTimeSeconds() < 0.1) {
                 limelight.toggleMode();
                 catalogManager.initiateCataloging();
             }
             if (!limelight.isMotifDetected() ||
                 catalogManager.getState() != Idle) break;
             sequenceManager.startShootingSequence();
             setPathState(1);
             break;
         // ... 10 more cases ...
     }
 }

 After (fluent API):
 public void init() {
     super.init();

     executor = new AutonSequence(follower, intake, catalogManager, sequenceManager, limelight)
         // Initial: scan and catalog preloaded balls
         .parallel(p -> p.limelightScan().catalog())
         .shoot()

         // Move to first pickup with intake
         .parallel(p -> p.moveTo(shootToFirst).intakeStart())
         .intakeStop()

         // Catalog while moving to shoot pose
         .parallel(p -> p.moveTo(firstToShoot).catalog())
         .shoot()

         // Second pickup sequence
         .moveTo(shootToSecondOne)
         .moveTo(shootToSecondTwo)
         .moveTo(shootToSecondThree)

         // Final shoot and park
         .intakeStop()
         .parallel(p -> p.moveTo(secondToShoot).catalog())
         .shoot()
         .moveTo(secondShootToStop)
         .build();
 }

 Implementation Plan

 Phase 1: Core Action Framework

 File: TeamCode/src/main/java/framework/Action.java
 - Create Action interface with methods: start(), update(), isComplete(), end(), getName()

 Files: TeamCode/src/main/java/framework/actions/*.java
 Create action implementations:
 - MoveToAction - wraps follower.followPath() and isBusy() check
 - CatalogAction - wraps catalogManager.initiateCataloging() and state check
 - ShootAction - wraps sequenceManager.startShootingSequence() and isExecuting() check
 - IntakeControlAction - wraps intake.runIntake()/stopIntake()
 - LimelightScanAction - wraps limelight.toggleMode() and isMotifDetected() check
 - DelayAction - simple timing utility

 Phase 2: Composite Actions

 File: TeamCode/src/main/java/framework/ActionGroup.java
 - Implement sequential execution mode (run actions one after another)
 - Implement parallel execution mode (run actions simultaneously until all complete)
 - Handle action lifecycle: start → update loop → completion check → end

 Phase 3: Execution Engine

 File: TeamCode/src/main/java/framework/ActionExecutor.java
 - Central executor that replaces switch/case state machine
 - Manages action lifecycle progression
 - Provides start(), update(), isExecuting() methods

 Phase 4: Fluent Builder API

 File: TeamCode/src/main/java/framework/AutonSequence.java
 - Fluent methods: moveTo(), shoot(), catalog(), intakeStart(), intakeStop(), limelightScan(), delay()
 - Parallel builder: parallel(p -> p.action1().action2()) for concurrent actions
 - build() method returns ActionExecutor

 Phase 5: Integration

 File: TeamCode/src/main/java/Autos/AutonTemplate.java (minimal changes)
 - Add protected ActionExecutor executor field
 - Modify start() to call executor.start() if executor exists
 - Modify loop() to call executor.update() if executor exists
 - Maintain backward compatibility with existing autonomous routines

 Phase 6: Example Refactor

 File: TeamCode/src/main/java/Autos/BlueBackAuton.java
 - Refactor existing BlueBackAuton to use new framework as proof-of-concept
 - Demonstrate 80% code reduction (213 lines → ~50 lines)
 - Keep existing path definitions unchanged

 Key Features

 Sequential Actions

 .shoot()
 .moveTo(pose1)
 .catalog()
 .shoot()
 Actions run one after another, waiting for each to complete.

 Parallel Actions

 .parallel(p -> p.moveTo(pose).catalog())
 .shoot()  // Only shoots when BOTH path and cataloging complete
 Multiple actions run simultaneously, advance when all complete.

 Intake Control

 .intakeStart()
 .moveTo(pickupPose)
 .intakeStop()
 Immediate actions that complete in one cycle.

 Complex Dependencies

 .parallel(p -> p.moveTo(shootPose).catalog())  // Wait for both
 .shoot()  // Only when in position AND cataloging done
 Natural dependency management through parallel groups.

 Benefits

 - 80% less code - 11 states reduced to fluent expression
 - Better readability - Matches natural language description
 - Reusable actions - Share across multiple autonomous routines
 - Type safety - Compile-time checking via fluent API
 - Easy debugging - Single executor vs scattered state logic
 - Parallel support - Native concurrent action execution
 - Backward compatible - Existing code continues working
